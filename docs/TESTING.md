# 测试说明

| 视角 | 本文定位 |
|---|---|
| WHY | 用可重复测试保护服务器权威状态、信任边界和持久化兼容性 |
| WHAT | 单元、集成、端到端、假进程/假网络与人工烟测边界 |
| HOW | 运行 `npm test`，再按覆盖矩阵定位失败；真实下载使用 smoke 流程 |
| ADR | 测试用于验证 [ADR 索引](adr/README.md) 中已接受决定的可观察后果 |

## 运行

```bash
npm test
```

测试全部使用 Node 内置 `node:test`，无额外测试依赖；当前基线为 165 个，用例数量以 `npm test` 输出为准。测试运行在临时目录和随机端口，不碰真实数据；网页标题解析通过注入假 fetch 测试，不触外网；浏览器托管通过注入假 spawn/exec 测试，不启动真实浏览器；缓存下载通过注入假 fetchInfo/download 实现测试，不起真实 yt-dlp 进程；时刻表 tick 通过注入时钟测试（`disableScheduler: true` 关闭 15 秒自动对齐）。所有集成测试传入 `disableCache: true` + 临时 `cacheDir`，避免触发真实下载、避免污染项目目录。

资产测试覆盖：带版本无损格式、运行态剥离、安装目录内外双保险库、内容去重与滚动历史、实时 JSON 损坏后的 `.bak` 恢复/隔离、无备份时拒绝空数据启动，以及 HTTP 导出后删除再完整恢复。

## 已知未覆盖（刻意留白）

- **前端 UI 交互**：电视端与遥控器是静态页，依赖浏览器环境，未做自动化 UI 测试。交付前需人工冒烟：开 `/tv/` 全屏 + 手机开 `/remote/` 走一遍完整流程。
- **真实下载链路**：`npm run smoke`（`smoke.js`）用真实 B 站链接走「登录 → 建单 → 贴链接 → yt-dlp 下载 → 缓存命名 → 状态装饰 → Range 流式 → ffmpeg 探针 → **建合集 → 抽一集入列 → 跳播验证第1集/第2集 → 合集条目 Range 流式 → 节目表导出**」全链路，已验证通过（1080p AV1 + AAC 合并成 mp4）。
- **断网重连**：两端 WS 都有 2 秒自动重连逻辑，靠人工验证（重启服务端观察两端自愈）。
- **大文件流式性能**：Range 逻辑已测，GB 级文件的吞吐未做基准测试——家庭千兆局域网远超播放码率，暂不认为有风险。

## 测试中的设计取舍记录

1. **WS 无 token 拒绝**：服务端完成 WebSocket 握手后以 `4401` 关闭（而非拒绝握手），测试断言 close code。
2. **消息竞态**：测试客户端内置消息缓冲（`ws.next()`），解决"消息先于监听到达"的丢消息问题——真实前端用 `onmessage` 常驻监听，无此问题。
3. **进程清理**：`server.close()` 会 terminate 所有 WS 客户端并销毁全部 socket，保证测试进程干净退出。
