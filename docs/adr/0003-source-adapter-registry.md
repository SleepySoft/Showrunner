# ADR-0003：网站源使用注册表与独立适配器

- 状态：接受
- 日期：2026-11-01

## 背景

不同网站在标题、合集入口和 yt-dlp flat-playlist 元数据上存在差异。把域名判断持续写进 `ytdlp.js` 会让执行器、站点规则和业务流程互相耦合。

## 决策

在 `src/sources/` 提供统一 `SourceRegistry`。站点适配器可实现 `matches`、`resolveTitle`、`analyzeCollection` 和 `normalizeYtdlpEntry`；专用合集分析返回 `null` 时自动使用公共 HTML/yt-dlp 适配器。

`ytdlp.js` 只负责启动进程、读取通用 JSON、下载和进度；API、合集、缓存和播放层不判断站点。

## 备选方案

- 在 yt-dlp 执行器中继续增加条件分支：文件少，但扩展和测试成本随站点数量增长。
- 每个网站实现完整下载器：自由度高，却重复进程、缓存和错误处理。
- 运行时加载第三方插件：扩展最开放，但当前家庭应用没有足够的签名、权限和兼容治理能力。

## 后果

- 新增网站通常只增加一个适配器文件、一行注册和对应测试。
- 统一接口必须保持小而稳定；新增钩子前应确认无法由公共上下文表达。
- 当前适配器仍随应用发布，不接受未经信任的运行时代码。
