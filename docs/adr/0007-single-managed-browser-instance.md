# ADR-0007：Showrunner 托管浏览器保持单实例

- 状态：接受
- 日期：2026-11-01

## 背景

维护模式曾通过系统默认浏览器打开普通窗口。服务端没有这个窗口的进程句柄，退出维护后只能启动新 kiosk，旧窗口仍可能继续播放，形成双播。只在退出维护时补关窗口不能解决快速模式切换、服务重启遗留进程和误杀用户浏览器的问题。

## 决策

普通 kiosk 与非 kiosk 维护窗口都由 `BrowserController` 通过配置的 Chrome/Edge 启动并保存进程句柄，各自使用带有 Showrunner 标记的独立 profile。

模式切换串行执行，并遵守“先等待旧受控进程树退出，再启动目标实例”。控制器拒绝在另一受控实例仍有引用时启动新浏览器。服务启动时还会按固定 profile 标记清理上次异常退出遗留的 Chrome/Edge；用户日常 profile 不匹配，因此不会被关闭。

## 备选方案

- 继续使用系统默认浏览器，退出维护时按窗口标题查找：标题不稳定且容易误杀。
- 允许 kiosk 与维护窗口并存，但静音其中一个：仍存在资源占用、状态竞争和恢复困难。
- 只保存 PID：正常切换可用，但服务崩溃后 PID 文件可能过期或被系统复用。

## 后果

- Showrunner 自己启动管理的浏览器在任意时刻最多一个，维护退出不会双播。
- 维护窗口不再复用用户日常浏览器，而是独立的受控非 kiosk 窗口；退出维护会被关闭。
- Windows 启动时需要一次只读进程枚举与针对固定 profile 标记的清理。
- 用户自己打开的 Chrome/Edge 不受模式切换影响。
