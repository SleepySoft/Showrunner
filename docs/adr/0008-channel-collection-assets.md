# ADR-0008：频道与合集作为独立用户资产

- 状态：已接受
- 日期：2026-11-01

## WHY

频道、合集、节目时间和时刻表不是可再生的运行缓存，而是用户长期整理的创作资产。只把它们放在安装目录中的一个运行状态 JSON，会同时暴露于文件损坏、误删软件目录、不完整导出和跨版本结构变化。播放位置、缓存和浏览器状态则不值得进入可分享资产。

目标是：升级不覆盖、误删程序后仍可恢复、可以无损导入导出、适合显式提交到版本库，并为后续结构迁移留下版本边界。

## WHAT

采用三层保护：

1. `data/showrunner.json` 是实时状态，写入前保留 `showrunner.json.bak`；解析失败时从备份恢复并隔离损坏文件，无备份则拒绝以空状态启动。
2. `data/asset-backups/` 保存资产当前镜像和 30 份滚动历史。原定的 `%LOCALAPPDATA%` 第二镜像位置已由 [ADR-0012](0012-confirmed-sibling-data-layout.md) 取代：现放在程序同级数据目录的 `asset-vault/`。
3. `.showrunner.json` 是可移植资产格式，带 `format` 和 `schemaVersion`，无损包含频道、节目字段、合集/游标与时刻表，但不包含密码、绝对媒体目录、缓存、播放位置和合集临时解析结果。

管理页支持下载、合并导入和完整替换。完整替换前仍会通过持久化链路留下历史版本。本地媒体以 `sourceName + relPath` 优先重新绑定，跨机器找不到时保留引用并报告数量。

## HOW

- `src/assets.js` 负责格式、校验、运行态剥离、内容指纹、原子写入与滚动历史。
- `src/store.js` 负责实时状态的原子替换、单代备份、损坏隔离和失败关闭。
- 服务启动时若实时文件不存在，会尝试从独立保险库恢复资产；若只是首次安装且无保险库，则创建空资产镜像。
- 只有资产内容指纹变化时才新增历史，播放心跳和进度写盘不会挤掉资产历史。
- 有意分享时，把管理页下载的文件放入仓库 `shared-assets/`；实时 `data/` 继续被 Git 忽略，避免无意提交播放进度和本机信息。

## 取舍

- JSON 仍是单机小数据量最易检查和搬迁的格式；这不是多实例并发数据库。
- 保险库保护程序升级和误删安装目录，但不能替代异机备份；磁盘整体损坏仍需把导出文件提交到 Git 或复制到其他设备。
- 当前只接受 `schemaVersion: 1`。实时状态缺少版本号时按旧版迁移；若版本号高于程序能力则拒绝启动，避免降级运行覆盖新数据。未来版本必须增加显式迁移器，不能把未知高版本当作当前格式读取。
