# ADR-0010：首次运行通过电视配对设置密码

- 状态：已接受
- 日期：2026-11-01

## WHY

Windows 生产运行使用无控制台的 `run-hidden.vbs`，并立即拉起 kiosk。把自动生成的永久密码打印到控制台与实际启动方式矛盾：用户看不到密码，也无法进入遥控器修改它。把明文密码写到固定文件或桌面虽然可见，却会留下长期凭据和清理问题。

## WHAT

未配置密码时不再创建永久密码，而是进入首次配对状态：

1. 服务进程生成一个仅在本次启动有效的 6 位配对码。
2. 只有通过 loopback 访问的本机电视 kiosk 能读取并显示配对码，同时显示可用的局域网遥控器地址。
3. 手机遥控器检测到首次设置状态后，要求输入配对码并直接选择 8–128 位长期密码。
4. 服务端验证配对码、限速失败尝试，将长期密码保存为 scrypt 哈希，签发会话并立即销毁配对码。

## HOW

- `loadConfig()` 在没有 `password/passwordHash` 时设置内存态 `setupRequired/setupCode`，不写配置文件。
- `/tv/setup-info` 只接受 `127.0.0.1`、`::1` 等 loopback 来源；局域网客户端不能通过接口读取配对码。
- `GET /api/setup/status` 只披露是否需要配对；`POST /api/setup` 接收配对码和新密码，连续失败 5 次后按来源地址冻结 15 分钟。
- 配对成功前普通 `/api/login` 返回 `409 setup_required`，未配置的 `Auth` 也拒绝空密码登录。
- 配对前若重启，旧配对码失效并生成新码；因为长期密码尚未设置，不存在需要找回的秘密。
- 配置写入 `passwordSetupVersion: 1`。升级时若发现旧版无标记哈希，会要求物理在场重新配对一次，以解救已经被不可见初始密码锁住的安装。

## 后果

- 静默启动、开机自启和 kiosk 模式都能完成首次设置，无需寻找控制台或日志。
- 首次设置需要用户能看到本机电视画面，这是有意采用的物理在场证明。
- 显式配置 `password`、`passwordHash` 或 `SHOWRUNNER_PASSWORD` 的自动部署继续跳过配对流程。
