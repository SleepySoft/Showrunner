# ADR-0011：本地媒体失败后按需生成浏览器兼容缓存

- 状态：已接受
- 日期：2026-11-01

## WHY

片库允许 AVI、TS、MKV、WMV 等常见家庭存量格式，但电视端实际由 Chromium 播放。浏览器支持取决于容器、视频编码和音频编码，扩展名不能可靠判断；例如 AVI 通常不可播，TS/MKV 内的 H.265、MPEG-2、AC3 或 DTS 也常失败。仅把 NAS 文件通过 HTTP Range 送给浏览器不能增加解码能力，失败后直接跳过又会让大量已有片库无法使用。

## WHAT

保留原始文件直播放在第一优先级。只有电视端明确报告 `MEDIA_ERR_SRC_NOT_SUPPORTED` 或 `MEDIA_ERR_DECODE` 时，才请求服务器使用便携 FFmpeg 把该文件转换为 H.264/AAC MP4：

- 原文件只读且永不修改。
- 转换产物存入 `cache/compatible/`，完成后自动重试当前节目，后续播放直接复用。
- 源文件大小或修改时间变化后，旧产物失效并重新转换。
- 独立缓存默认上限 10GB，按最近使用时间淘汰。
- 转换开始、失败及原播放异常写入结构化播放日志，并在遥控器“日志”页展示。

## HOW

电视端遇到上述两类错误时发送 `compatibilityRequest`，不发送会导致立即跳台的普通 `playbackIssue`。服务端复核 `qid` 必须仍是当前节目，再通过片库 ID 取得受信任绝对路径并启动 `CompatibilityManager`。任务状态通过现有状态广播装饰到当前节目；`pending/transcoding` 显示等待画面，`ready` 切换到支持 Range 的 `/compatible/:id/stream`，`failed` 记录原因并按原异常策略跳过。

诊断 API 只返回结构化事件和转换摘要，不返回片库绝对路径或原始服务端日志。FFmpeg 错误中的源路径在持久化前替换为占位文本。

## 后果

- AVI、TS、MKV、WMV、旧编码 MP4 等只要 FFmpeg 能解码，均可通过转换播放。
- 首次转换可能接近片长并消耗 CPU、磁盘和 NAS 带宽；因此不预先批量转码，也不改写整个片库。
- 转换完成前当前频道保持等待，不会误跳过；转换失败仍会留下可见日志并继续下一节目。
- 此方案优先保证兼容性和可恢复性，不承诺实时转码或保留原始多音轨、字幕和无损质量。
