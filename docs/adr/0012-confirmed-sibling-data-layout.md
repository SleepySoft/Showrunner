# ADR-0012：程序与数据使用同级双目录，旧数据迁移必须人工确认

- 状态：已接受
- 日期：2026-11-01

## WHY

把 `config.json`、实时状态和大体积缓存放在代码目录中，会让更新、重新解压和删除程序带上不必要的数据风险；放入 `%LOCALAPPDATA%` 又不符合便携部署和用户希望直接看见、整体搬运数据的习惯。旧部署已经积累了频道、合集、密码哈希和缓存，程序不能在升级后自行判断并静默搬动这些资产。

## WHAT

默认把安装目录 `showrunner/` 与用户数据目录 `showrunner-data/` 并列放置。数据目录保存配置、状态、资产历史、日志以及网页/兼容缓存；程序目录只保存可由发布包替换的代码、运行时和工具。高级部署可用 `--data-dir` 或 `SHOWRUNNER_DATA_DIR` 覆盖默认位置。

发现程序目录内的旧版 `config.json`、`data/` 或 `cache/` 后，服务进入迁移门禁而不是正常播放：

- 不加载业务状态，不启动缓存任务，不写新旧配置。
- 本机电视显示一次性六位确认码，手机遥控器输入确认码后才能选择操作。
- 可选择迁移旧数据、使用已经存在的同级数据目录、创建全新目录，或暂不迁移并退出。
- 新旧目录同时有内容时必须明确选择，不能按时间或文件数量猜测。

## HOW

`storage-layout.js` 只在启动时检测并生成计划；检测本身没有文件写入。确认迁移后，旧配置、状态和缓存先复制到同级临时目录，内部指向旧程序目录的路径覆盖会被移除，JSON 与文件数量/字节数校验通过后再原子改名。旧目录永不自动删除；若目标目录原本有内容，先改名为带时间戳的 `before-migration` 备份。

迁移成功后写入带 `layoutVersion` 的 `storage-layout.json`，后续启动据此直接使用同级数据目录，不重复询问。更新器只覆盖程序目录，更新包、日志和更新前快照均写入数据目录。

## 后果

- 更新或重新解压程序不再需要依赖一长串排除规则保护用户数据。
- 数据仍在程序旁边，用户可以直接查看和整套复制，不依赖 Windows 用户目录。
- 首次升级需要一次电视确认；这是保护资产的有意摩擦。
- 保留旧数据和复制缓存会临时占用额外磁盘空间，但能保证迁移失败或回退时仍有完整来源。
- 同一磁盘或父目录整体损坏仍会同时影响程序与数据，因此 `.showrunner.json` 外部备份仍然必要。
